# Mini SRS — QR Attendance System

## 1. ภาพรวมระบบ
ระบบเช็คชื่อเข้าเรียนผ่าน QR Code สำหรับวิชา SIT0013 (SEC N01)
ทดแทนการเรียกชื่อ ใช้ QR ที่หมุน token เพื่อป้องกันการเช็คชื่อแทนกัน
บันทึกผลลง Google Sheets และแสดงรายงานสรุปมา/ขาด

## 2. ขอบเขต
เฉพาะวิชา SIT0013 ที่อาจารย์สมคิดสอน ไม่รองรับหลายวิชาใน MVP
ไม่มีการแยก "สาย" ใน MVP (เพิ่มใน sprint ถัดไป)

## 3. Functional Requirements

| ID | รายละเอียด | เชื่อมกับ |
|---|---|---|
| FR1 | อาจารย์สร้าง session เช็คชื่อ (ระบุวันที่/คาบ) | UC1 |
| FR2 | ระบบแสดง QR Code ที่หมุน token ใหม่เป็นระยะระหว่าง session เปิดอยู่ | UC1 |
| FR3 | นักศึกษาสแกน QR แล้วกรอก/ยืนยันรหัสนักศึกษา | UC2 |
| FR4 | ระบบตรวจสอบความถูกต้องของ token ก่อนบันทึกผล | UC2 |
| FR5 | ระบบบันทึกผลการเช็คชื่อลง Google Sheets (sheet attendance_log) | UC2 |
| FR6 | อาจารย์ดูหน้ารายงานสรุปมา/ขาด ต่อ session | UC3 |
| FR7 | ระบบมี master list รายชื่อนักศึกษา (sheet students) เก็บล่วงหน้า | UC3 |
| FR8 | หน้าสแกนตรวจสอบรหัสนักศึกษากับ master list ก่อนบันทึก | UC2 |

## 4. Non-Functional Requirements

| ID | รายละเอียด | เหตุผล |
|---|---|---|
| NFR1 | รองรับการสแกนพร้อมกัน ~35 ครั้งในช่วงเวลาสั้น (ต้นคาบ) | ขนาดห้องจริง 33 คน |
| NFR2 | QR token หมุนเปลี่ยนทุก ~15 วินาที | ป้องกัน proxy attendance |
| NFR3 | Token ตรวจสอบได้แบบ stateless ไม่พึ่ง state ที่แชร์ระหว่าง request | ข้อจำกัด Vercel serverless |
| NFR4 | เก็บข้อมูลเท่าที่จำเป็น จำกัดสิทธิ์เข้าถึง Sheets เฉพาะอาจารย์ | PDPA |
| NFR5 | ใช้งานได้จากเบราว์เซอร์มือถือทั่วไป ไม่ต้องติดตั้งแอป | ลดแรงเสียดทานนักศึกษา |

## 5. Use Case Summary
UC1 สร้าง session และแสดง QR (อาจารย์)
UC2 สแกนเช็คชื่อ (นักศึกษา)
UC3 ดูรายงานสรุป (อาจารย์)
